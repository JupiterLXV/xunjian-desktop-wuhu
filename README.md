# 巡检缺陷命名分类工具 · 芜湖版

当前版本 **50.4.4**。基于仓库最新主分支增量修复模板导入与窗口图标；保留已合入的直接启动、红外跳过和 Excel/Word 报表功能。

## 使用

1. 运行 `Xunjian-Wuhu-Setup-50.4.4-x64.exe`，选择安装位置。目标为 Windows 10/11 x64。
2. 延续最新主分支的直接启动方式，不需要导入授权文件。
3. 选择原始照片目录及成果目录。照片目录推荐为 `线路/主线或支线/#001/照片`；也支持在其中一级打开，按选择目录的真实完整路径补充祖先。
4. 检查右侧“线路 / 主支线 / 杆号”；非标准层级会提示手动确认。DJI 时间戳、序号及 `_T/_V` 不参与命名，也没有增加 T/V 过滤。
5. 绘制一个或多个同类缺陷红框，在原缺陷列表中选择一条完整规则。唯一等级直接随规则选定；“柱上开关—鸟巢”的严重和危急分别展示，必须明确选择。
6. 小图默认围绕最大红框；通过下拉框或点击已有红框切换目标，滑杆调整周边范围。“恢复自动”还原目标及余量。直接保存即可使用推荐范围。
7. 每次普通或危急保存均生成一张完整大图、一张局部小图、一份原始 JPEG 字节副本，位于成果目录下的 `大图/`、`小图/`、`原图/`，两张同名 JPG：

   `10kV枫墩188线-良久支线-#001-横担端U型挂板-螺母松动-严重.jpg`

原始照片不变，白色裁剪虚线不会导出。小图直接裁剪原始分辨率照片，没有 AI 重绘。选择不同照片时，各自的框和裁剪设置独立保存。

## 与旧版有关的行为

- 不添加前置编号或新的重名弹窗。**原版已经有重名编号**：正常再次保存更新当前组；“清除并二次编辑”创建新组，同名时沿用 `（2）`、`（3）` 后缀。该策略原样保留；大小图同步使用同一后缀。
- 主保存新增的“原图”只保存已确认缺陷的源 JPEG，不批量复制。兼容原先仅有大小图的历史组。主保存不再创建“缺陷原图”“缺陷圈示图”“危急缺陷”或全绝缘分类子目录。“保存危急大小图”同样保存到大图、小图，并要求选中危急规则。
- 已有旧成果不会自动迁移或删除。读取、刷新、成果管理、回收站仍兼容旧目录。原“全绝缘分类”入口给出当前平铺规则提示，不再移动新成果到子目录；“补全缺失小图”仅处理有裁剪记录的新成果，不把旧原图当成小图。
- 保留隐藏的成果索引、事务恢复目录和回收站，用于原图对应、配对、失败回滚及恢复。成果中不再包含 DJI 原名，**备份时应保留 `.xunjian-output-v1.json`**；丢失索引后，同杆同类的多张原图不能可靠反推归属，程序不会猜测。
- 首次默认预设来自 `app/wuhu-rules.json`（45 条、14 类）。导入后以当前 JSON 字典完整生成分类、规则、等级与命名，不受默认列表限制；覆盖、合并、自定义分类与标签均可持久保存。

## 性能和原界面

原 1440 像素预览、按需高清、三路 Worker 解码、相邻图预加载、48–96 MiB 预览预算、缓存淘汰、高清位图释放、虚拟目录树、11 种主题、背景图片、黑夜模式、动效与快捷键保留。小图预览使用已有缓存，不新增原图解码；成对导出在独立 Worker 中从原始文件解码一次，依次编码大图和小图，沿用 JPEG 0.95 质量。

修改 `getImage` 的范围仅是为新成果选取干净原图，防止对已烘焙红框的 JPG 再次压缩/绘制；缓存和解码主体通过原版源码哈希校验。保存前继续沿用原有高清释放与预加载调度。新增面板复用原主题变量，原有全部内嵌 CSS/主题背景逐字节校验。

默认每侧余量 35%，滑杆 10%–150%。相邻红框仅在与裁剪范围相交、合并后面积不超过初始范围 2 倍时纳入。边缘选区平移到图像内，保留目标，输出不拉伸、不补黑边。无有效框时禁止缺陷双图保存。

## 开发

使用 Node.js 24 与 npm；无运行时第三方依赖。

```sh
npm ci
npm start
npm test
npm run dist:win
```

- `app/main.cjs`、`preload.cjs`：Electron 入口和隔离 IPC。
- `app/renderer.js`、`index.html`：恢复的原界面和浏览/编辑算法。
- `app/wuhu-core.js`、`wuhu-rules.json`、`wuhu.css`、`boot.js`：本次规则、目录命名、裁剪和预览接入。
- `app/fs-service.cjs`、`output-ops.cjs`、`output-trash.cjs`：原文件服务、事务恢复和成果回收站。
- `tests/`：纯逻辑、报表、红外跳过、模板、源码保留校验及真实 Electron 渲染器回归。测试在临时副本中注入观察接口；**测试宿主与接口不会进入安装包**。
- `docs/IMPLEMENTATION_GUIDE_v1.0.md`：原需求基线；`docs/performance-baseline.json`：原版性能和资源校验值；`docs/DELIVERY.md`：本次实际验证和限制。

图片预览测试直接使用安装的 Electron，不依赖下载另一套 Chromium。Windows 上 `npm test` 包含生产激活页及真实 MachineGuid 的检查；Linux 中该项明确跳过，其余真实渲染器测试可用无显示设备方式运行。

Linux 交叉构建：`npm run dist:win:linux`。当前受限环境无法运行 Wine 的本地套接字，该脚本使用锁定的 electron-builder 自带 `UninstallerReader` 提取真实 NSIS 卸载器，而不执行临时 Windows 程序；不修改依赖文件，不修改应用。此操作不代表已在 Windows 运行安装器。

## 通过手机 Work 持续维护

仓库连接获得本项目写入权限并提交后，直接向 Work 提供本仓库链接和修改要求即可，无需继续依赖 ASAR 恢复。

`.github/workflows/windows-build.yml` 在 `main` 更新或手动运行时，使用 Windows runner 安装锁定依赖、运行测试、构建 NSIS 安装包、检查包内源码、静默安装并验证直接启动、快捷方式与实际窗口图标，最后上传安装包、SHA256 与测试报告。不会创建 Release 或自动公开发布安装包。

在 GitHub 手机网页打开仓库 → Actions → Windows installer → 成功记录 → Artifacts → `Xunjian-Wuhu-Windows-x64`。Artifacts 默认保留 30 天。以后由 Work 修改代码、测试并提交，自动构建即可重用。

## 恢复边界

原 ASAR 只有生产 `package.json`，不包含 Electron 原始版本、开发依赖、依赖锁、构建脚本、NSIS 原配置/升级 GUID 或代码签名证书。这些不能声称“完全还原”。现已补齐并锁定 Electron 45.5.0、electron-builder 26.18.0、Playwright 1.65.1、构建脚本和标准 NSIS x64 配置。

当前未提供 Windows 代码签名证书，产物不签名；EXE 资源编辑已开启，原 Logo 写入窗口、任务栏、EXE、快捷方式和安装/卸载器。原安装器升级 GUID 无法恢复。当前主分支已移除授权门；此修复保留该行为。


50.4.1 的根因、三份成果和验证边界见 [修复说明](docs/50.4.1-validation.md) 与 [变更记录](CHANGELOG.md)。三份同名 JPG 原图字节不变的模式要求源文件为真实 JPEG；非 JPEG 保留浏览并明确提示，不转换或伪装。

50.4.2 的动态模板、持久化及任务栏图标修改见 [修复说明](docs/50.4.2-validation.md)。
