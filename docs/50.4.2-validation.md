# 50.4.2 模板与任务栏图标修复

基于 9abf130（包含已合入的红外跳过、Excel/Word 导出及直接启动）。未恢复旧项目、旧授权门或修改这些新增模块。

## 根因与修改

- `defItemHtml` 只接受内置 `WuhuRules` 的标签，未知规则返回空 HTML；分类数量却在调用前计算，所以出现 16 条只显示 3 条等现象。`appendDefect`、文件名预览和保存同样使用旧规则白名单，单改渲染仍无法保存。
- `loadDefectDict` 重启时以默认字典为基准进行交集过滤，自定义规则再次丢失。`loadCriticalDefects` 也丢弃已保存的模板等级设置。
- 当前字典现在是唯一的标签成员和字段来源；字典或危急属性修改时，版本号触发动态索引重建。内置规则只作为首次默认值、显式重置来源以及相同规则的可选备注，不限制导入成员。
- 完整标签 `_部件-描述-等级` 按模板字段保存；旧式自定义标签没有等级时沿用危急集合，否则采用“一般”，仍生成六字段 JPG。分类/标签顺序、增删改和合并导入继续使用现有交互。
- 导入清理对应旧隐藏状态，重启保持当前字典、推荐规则和危急设置，不自动合并或复活默认标签。没有修改主题 CSS 或面板布局。
- 原版 PNG 通过 ASAR 感知的文件读取创建 NativeImage，并传给构造函数及 `setIcon`，显式设置运行窗口图标。原 ICO、EXE 资源和 AppUserModelID 不变。Windows 安装测试新增 WM_GETICON 检查实际大小窗口图标，并与原版 PNG 比对；用户已有固定图标缓存仍需在目标机确认。

## 自动验证

回归使用实际导入文件（26 分类、147 条规则）：逐分类核对可见数量和全部 data-text，选择此前被隐藏的五个示例分类的新规则，真实保存三图并核对文件名与原图字节。用真实界面新增分类与无等级自定义标签、保存；退出并重新启动后复核全部规则与危急集合。继续验证合并、覆盖为任意新分类、再次重启后旧默认规则不复活。

原有单元、报表、红外跳过、三图事务、11 主题、性能算法/缓存/虚拟树和生产入口测试保留执行。具体结果以本次交付说明和 Actions 日志为准；未执行测试不会标为通过。
