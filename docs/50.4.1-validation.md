# 50.4.1 修复与验证

本版本以后续 50.4.1 用户要求为准，新增“原图”取代原 v1.0 指南中的禁止新增原图目录规定。原指南保留为历史需求基线。

## 已定位的根因

50.4.0 的 `_rawParseFilePrefixAndLocation` 返回 `loc: ''`。原虚拟树 `rowHTML` 用 `p.loc` 作为照片文字，因此节点、选中背景和状态都在，只有名称为空。这是显示模型与渲染器的接口错误，并非 CSS。50.4.1 在解析结果中恢复原照片名（不带扩展名），不改变虚拟树算法或原样式。最终命名依旧单独来自目录三字段与规则三字段，DJI 文件名不进入成果名。

另两项会阻断保存的条件已修复：旧 IndexedDB 目录句柄缺少 `sourcePath` 时，在选中支线/杆号目录后无法恢复祖先；50.4.0 对支线名硬性要求以“线”结尾，会清空带括号等真实支线的三字段。现在按文件服务真实授权路径刷新旧句柄，保留实际目录名称。异常层级继续允许手动纠正。

50.4.0 的保存按钮只按队列判断禁用，但目录同步时全局 IO 捕获会阻止点击，造成按钮可用却没有保存。现在按钮禁用条件同步覆盖 IO、切图和本图保存，忙碌提示明确，等待结束后自动恢复。

## 三份成果

仅对当前确认保存的缺陷照片保存三份，配对标识、同名避让、事务日志及索引共用。原图沿用保存快照中的原始 JPEG Blob，不进入 Canvas、Worker 编码或压缩。大图和小图仍由原始像素在后台 Worker 导出。复制原图复用已有原始 Blob，异步分块写入，不额外解码原图。

原图和输入的 SHA256/字节比较覆盖普通 JPEG、嵌入元数据、EXIF 旋转图；三份同名、二次编辑、删除、恢复、失败回滚和旧两文件组升级均纳入回归。未保存的照片不复制。非 JPEG 仍可浏览，但明确拒绝伪装成“未经重新编码的 JPG”。

旧版两文件组保持可读、可删除恢复，直到用户明确保存该照片才添加原图。没有批量迁移或复制，没有新重名策略；原有正常更新、二次编辑 `（2）` 等行为保留。

## Logo

原 `app/icon.png` 与 ASAR 校验值相同。`app/icon.ico` 仅为该 PNG 的 16/24/32/48/64/128/256 尺寸转换。50.4.0 的 `signAndEditExecutable: false` 使主 EXE 保留 Electron 图标；改成 `signExecutable: false` 后保留真实图标和版本资源写入。

窗口使用 ICO，AppUserModelID 保持 `local.xunjian.desktop`；任务栏的重启动图标指向实体 EXE（Windows Shell 无法读取 ASAR 内的虚拟 ICO 路径）。两种快捷方式也指向该 EXE。安装/卸载配置明确使用同一 ICO。PE 资源校验直接检查产物中的图标数据来自原 ICO，而非只检查配置。

安装完成后发送 SHChangeNotify 关联刷新通知，不删除缓存或重启资源管理器。旧电脑的固定任务栏图标缓存是否刷新，必须在该电脑检查；必要时从新程序取消固定后重新固定。

## 测试边界

原版关键性能算法、主题 CSS/背景、授权模块和公钥继续逐字节校验。实际渲染器回归覆盖可见文件名及真实文件绑定、切换/已看/保存、三份事务、元数据、裁剪、视图刷新、旧成果、11 主题和后台 IO 忙碌状态。大数据用 96 张真实合成 JPEG、连续切换样本和 5000 项虚拟目录树检查缓存与渲染范围。

GitHub Windows 工作流包含生产激活门、MachineGuid、Windows NSIS 构建、安装与启动、安装/卸载 EXE 图标资源、桌面和开始菜单快捷方式，以及可用时的 Windows 本机 SMB UNC 共享测试。公司 NAS、公司真实授权文件和用户机器上旧图标缓存不在此环境，不能据此标为通过。具体执行结果以本次交付说明及 Actions 日志为准。
