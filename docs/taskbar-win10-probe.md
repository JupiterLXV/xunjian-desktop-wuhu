# Win10 任务栏白纸：目标机对照工具

当前反馈：从未固定任务栏、Alt+Tab Logo 正确、Windows 10；重启、清理图标缓存以及移除 `setAppDetails` 均未解决。旧固定入口不是排查方向，具体根因仍待目标机取证。

`scripts/diagnostics/build-taskbar-probe.cjs` 将 PowerShell 源码生成单文件 CMD。打开现有巡检程序后双击运行，按三个阶段分别记录任务栏是否显示正确 Logo：

1. 保留运行窗口的当前属性，读取基线。
2. 明确指定从正在运行的 ASAR 中提取的原版 ICO，窗口身份设为原应用 ID。
3. 继续使用相同 ICO，仅切换为独立的临时窗口身份。

结束或取消时恢复原窗口属性，并逐项读回核对；重新启动应用也会清除本次临时窗口设置。程序、照片、快捷方式和注册表均不修改，不清缓存、不重启 Explorer。输出仅保存在本机桌面：Windows 版本、真实 EXE 路径和版本、运行中 ASAR 的版本/哈希、窗口图标与属性、巡检快捷方式属性、任务栏区域截图和人工选择结果，打包为 `Xunjian-Taskbar-Diagnostic-日期时间.zip`。工具不自动上传数据。

阶段 2 改善，优先检查原身份下任务栏图标来源；阶段 2 无效而阶段 3 改善，优先检查旧应用身份关联。两者都无效则保留证据继续检查目标 Win10 Shell 的取图行为。这些是缩小范围的方法，不能单独证明某一项为最终根因。

自动化验证使用 Windows Server 2022 的真实 Explorer 桌面、实际安装的 50.4.4 程序及其现有窗口，检查原图标哈希、属性切换与恢复、ASAR 和快捷方式字节不变。自动模式的人工观察字段明确为 `not-executed`；不代表已在用户 Win10 电脑验证，也不代表白纸问题已修复。

本次不修改任何 `app/` 生产文件，不升级应用版本。此前使用的是干净安装的 Server 桌面，其截图无法代表用户已有安装环境。安装器保留快捷方式的分支仅在特定升级条件下生效；不能据此断言用户通过正常安装向导升级时一定保留了旧链接。
