## 1. 执行方式与源码恢复

1. 确认仓库权限、当前分支和 `app.asar` 来源。优先检查仓库是否已有完整源码；若已有，先核对其与当前 ASAR 的版本关系，避免用旧源码覆盖新版本。
2. 若只有 ASAR，使用与项目兼容的 Electron ASAR 工具解包（例如 `npx @electron/asar extract app.asar recovered-app`，实际命令按环境核验），保留原 ASAR 作为基线。不要直接对二进制文件盲目修改。
3. 检查 `package.json`、主进程、preload、renderer、HTML/CSS/JS、资源、IPC、依赖、授权逻辑、图片编辑与保存代码；确认现有 Electron 版本与 Windows 构建配置。若原构建配置/依赖锁文件/素材缺失，则据实补齐可恢复部分，记录假设与缺项，不伪称还原了原始开发环境。
4. 先建立可运行基线，再做增量修改。尽量沿用原有技术栈与目录组织，禁止为了本次更新重写整个程序。保留机器码授权及验证行为，不绕过、不削弱；不要上传私密签名密钥、授权凭据、公司巡检数据或真实图片。若现有源码含敏感信息，报告并按授权处理，不传播到公开仓库或构建日志。
5. 保留基线文件或可追溯提交；以清晰的提交记录实现修改。不擅自删除原始文件，不未经许可公开仓库。

## 2. 原始图片目录与路径识别（已确认）

原始照片的典型结构如下，线路、支线和杆号均来自真实目录，不是从 DJI 文件名推断。


- 选中图片时自动从其所在目录提取：线路名称、主线或支线名称、杆号。保持中文、数字、`#`、前导零及目录原始名称；不得凭空补写或从原文件名取编号。

唯一命名格式：

```text

```


- 前三项自动读取目录；后三项由用户选择新版缺陷规则后获得。
- **不添加任何前置编号**。参考旧成果中的 `1011` 等前缀属于人为错误，不得沿用。
- 连接符为半角连字符 `-`；缺陷描述内部的中文顿号、逗号等保持原样。
- 同一组成果的大图、小图文件名完全一致（包括扩展名），仅保存目录不同。
- 用户明确取消新增同名冲突检测：不额外增加冲突弹窗、自动编号、后缀或新重名策略；原程序已有的保存行为保持不变，并在交付说明中如实写明重名时实际行为。不要借本次更新引入新的覆盖行为。

## 6. 红框与大小图导出（已确认）

### 6.1 业务含义

一张原始图片对应一种缺陷命名规则，但允许圈出多个属于该缺陷类型的红色矩形标记。最终每次保存只生成一张大图、一张小图，而非每个红框各输出一组图片。

- **大图**：保留完整原图画面及用户绘制的全部红框；不得因小图选区而裁剪。延续现有的大图导出质量和画面方向，不包含界面按钮、预览虚线等操作控件。
- **小图**：从原始图片的实际像素范围中，围绕一个代表性红框裁剪局部，尽量突出缺陷本身，同时保留必要的周边设备结构。裁剪范围若自然包含邻近红框，则一并保留；距离较远的红框无需包含。小图不是简单等比例缩小整张大图，也不是将多个离散位置拼接成一张图。
- 两张均保留适当可见的红框标注，均导出 JPG；保持真实照片内容，不用 AI 重绘、补画或生成细节，不改变原图。

示意（用户参考图中，大图有左侧一个红框及右侧上下两个红框；小图仅围绕右侧局部）：

```text
大图（完整画面）                  小图（代表性局部）
┌────────────────────┐            ┌────────────┐
│            ┌────┐  │            │  ┌────┐    │
│  ┌──┐      │红框│  │            │  │红框│    │
│  │框│      └────┘  │     →      │  └────┘    │
│  └──┘      ┌────┐  │            │  ┌────┐    │
│            │红框│  │            │  │红框│    │
│            └────┘  │            │  └────┘    │
└────────────────────┘            └────────────┘
```

### 6.2 自动裁剪策略（用户认可的功能方向；具体数值为建议默认值）

1. 将红框统一保存为原图坐标或归一化坐标；屏幕缩放、平移、窗口变化、DPI 和图片方向变化后仍准确对应原图。
2. 默认选面积最大的有效红框作为代表性裁剪中心；面积相同可按绘制顺序稳定选择。用户可切换目标红框，默认策略不能覆盖用户本次手动选择。
3. 默认在目标框四周留出适当余量（建议每侧约为目标框对应宽高的 35%，实际数值可结合效果调整），保留缺陷附近的设备结构。不得人为固定裁剪为正方形，也不必覆盖全部红框。
4. 对距离很近的其他红框，可将其纳入裁剪范围，前提是不显著牺牲局部细节。建议只在扩大后的范围仍约为原默认裁剪范围面积的 2 倍以内时考虑合并；该阈值为初始实现建议，不是用户规定。优先保证目标红框完整、细节突出，避免把远处红框强行纳入。
5. 裁剪范围必须限制在原图边界内。目标靠边时优先平移有效裁剪区域，必要时缩减余量；不得增加黑边、拉伸或裁掉目标缺陷。显示范围内的其他红框同步正确裁剪/绘制。
6. 最终导出从原始分辨率图像读取像素，而非截图编辑窗口或裁剪低清缩略图。依据原图方向、编辑变换及裁剪偏移正确映射红框；避免不必要的二次 JPEG 压缩。
7. 若没有有效红框，不得凭空生成小图或随机裁剪；对当前缺陷双图保存操作给出明确提示。原有非缺陷处理功能不因此被禁止。

## 7. 小图预览和调整（用户已认可）

在现有编辑界面中新增小图预览能力，尽量融入原 UI，不另起独立繁琐流程。

### 7.1 交互布局

```text
┌────────────────────────────────┬──────────────────────┐
│ 原有大图编辑画布               │ 小图实时预览         │
│ 用户绘制一个或多个红框         │ 展示裁剪后的真实画面 │
│ 可显示白色虚线裁剪范围         │ 保留局部红框         │
│                                ├──────────────────────┤
│                                │ 裁剪目标：框1 / 框2…│
│                                │ 裁剪范围：──●────    │
│                                │ 恢复自动（建议）     │
└────────────────────────────────┴──────────────────────┘
```

- **自动预览**：创建红框后立即产生推荐小图，增加、移动、调整、撤销或删除红框时及时更新。无需用户额外点击生成按钮。
- **选择裁剪目标**：有多个红框时，可以通过点击大图中的框或简洁的目标切换控件选择代表性缺陷（实现方式按现有 UI 决定）。只影响小图，不改变大图中其他红框。
- **裁剪范围**：滑杆调整目标附近的保留范围，实时更新小图，提供由紧凑到宽松的合理范围，避免裁掉目标红框。
- **预览范围指示**：可在大图上显示白色虚线裁剪边界；仅用于编辑提示，不得出现在任一导出图片中。
- **最终保存**：用户不调整时直接使用自动推荐结果；有手动调整时必须使用当前预览所对应的裁剪范围，所见即所得。切换原图后不得错误沿用上一张的坐标或选区。
- 可提供“恢复自动”快捷操作。具体布局、滑杆范围、默认余量及合并阈值由 Work 结合现有界面决定并记录；不要将额外设置变成每张图的必填步骤。

### 7.2 性能与渲染建议

- 优先复用现有图片加载、Canvas/绘图与导出实现。预览可用缩放缓存，最终导出用原图像素坐标。
- 正确处理高分辨率图片、不同长宽比、缩放和平移，避免重复解码导致卡顿或内存增长；切换照片时释放不再需要的图像对象及资源。
- 标记线宽应在大图和小图中均清晰可辨，不遮挡关键设备细节。遵循原程序标注风格；必要时按输出像素尺度调整描边。
